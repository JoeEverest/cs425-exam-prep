Draw a Collaboration Diagram

≈ 20 minutes · pen and paper required at the end · cheat sheet · ← Lesson 4

Why this lesson. This is a conversion skill. You already own the story — the Lesson 4 sequence diagram. Here you re-project it: links instead of lifelines, numbers instead of vertical order. Exams often hand you one diagram and ask for the other.

What the exam asks

  • Explain the emphasis: a collaboration diagram shows object links and message exchanges; a sequence diagram shows time order.
  • Show the participating object instances and the structural links between them.
  • Number the messages to show order, nesting, and control flow.
  • Assign each message to the responsible boundary, control, or entity object.
  • Tell the same story as the use-case flow and the sequence diagram, with the validation and alternatives.

Exam phrasing to memorize: "a collaboration diagram emphasizes object links and message exchanges; a sequence diagram emphasizes time order."

The numbering system

The numbers carry everything the vertical axis carried before. Three rules:

  1. Top level: each message from the actor starts a new whole number: 1, 2, 3.
  2. Nesting: while an object handles message n, every message it sends gets n.1, n.2, n.3 — in order. Deeper delegation adds another dot: 1.1.2.
  3. Control flow: guards ride in front of the label: 1.1.4 [prereqs met]: create(...). A repeated message takes a star: 2.1 *[for each book]: borrow(bookId).

Read 1.1.2 aloud: "the second message sent while handling 1.1." If you can say that sentence for every number you wrote, your numbering is right.

2

Draw the links

One solid line for every pair that exchanges at least one message in the sequence diagram: actor–form, form–controller, controller–repository, controller–course, controller–enrollment. These lines are structure — they say "these objects know each other."

3

Walk the sequence diagram, label the links

Go down the Lesson 4 diagram message by message. Write each label along its link with a small arrow for the direction. Do not invent and do not skip — this is a transcription.

Returns stay home: the confirmation and the rejection are return traffic, so they get no numbered message here.

4

Number, then add the guards

The actor's message is 1. The form sends 1.1. The controller, handling 1.1, sends 1.1.1 through 1.1.4 in order. The branch outcomes of BR-1 become guards on 1.1.3 and 1.1.4. Done — the complete diagram:

Two messages ride the controller–course link (1.1.2 and 1.1.3) — one link, two labels. That is normal; links are structure, messages are traffic.

Red-pen list: how students lose marks here

  • Flat numbering. 1, 2, 3, 4, 5 across the whole diagram throws away nesting — the control flow the question asks for.
  • Numbering jumps a level. The controller handles 1.1, so it sends 1.1.1 — not 1.2. The prefix is the message being handled.
  • Missing links. A message floating between two unlinked boxes. Draw the line first, the label second.
  • Story drift. A message here that the sequence diagram does not have, or the reverse. It is a transcription, not a remix.
  • Guards dropped. The BR-1 branch must stay visible — that is the "relevant validation" the guide demands.
  • Actor omitted. Message 1 needs a sender. Keep the stick figure.

Quick check

1 · What does a collaboration diagram emphasize that a sequence diagram does not?

Links show structure and coupling. Time order moves into the message numbers. This exact explanation is an exam bullet.

2 · The controller, while handling message 1.1, sends its third message. Its number is:

Prefix = the message being handled (1.1), suffix = the send order (3). "The third message sent while handling 1.1."

3 · How does the BR-1 branch from the sequence diagram's alt frame appear here?

Guards carry the condition. (A complex alternative flow can still get its own diagram — same rule as Lesson 4.)

4 · The member scans a second item, and the actor's message repeats for each book. Best notation?

The star marks iteration; the bracket says over what. One line replaces any number of repeats.

5 · Two messages travel between the controller and the Course object. How many links do you draw?

A link says "these objects know each other" — once. Messages are traffic on that link.

Grade yourself

  • Six boxes with colons, actor included; no lifelines, no activation bars.
  • A link for every communicating pair — and only for those.
  • The card scan is 1; the book scan starts 2 — a new actor message, a new whole number.
  • Nesting reads correctly: 2.1 sent by the kiosk, 2.1.1 and 2.1.2 sent by the controller.
  • BR-1 and BR-2 visible as guards; iteration star on the repeated scan.
  • Every message exists in your Lesson 4 diagram — no drift.

Score 5–6: say "next" for Lesson 6. Score ≤ 4: renumber only — say each number aloud as "the nth message sent while handling…" and fix what does not parse.
